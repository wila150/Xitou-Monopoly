# LINE 闖關系統｜國介＆禾康溪頭大富翁

依據 `LINE闖關系統_架構設計文件(2).docx`（v2 版）為基礎、再依實際討論調整過的 LINE 官方帳號後端。全程以 LINE 文字指令驅動，小編不需要另外的網站後台。

## 遊戲機制

- **12 關分三種過關方式**（`src/config/checkpoints.json` 的 `verifyType`）：
  - **`keyword`（A3、A5）**：關主評估完成後口頭給關鍵字（目前每關 10 組共用同一個關鍵字，就是關卡代號本身，例如 A3 關的關鍵字就是「A3」），隊伍打進 LINE 立即解鎖下一關。
  - **`referee`（B3、B4、D6、C4）**：隊伍不用輸入任何東西，關主現場確認完成後，直接由關主或小編輸入「通過 X組」解鎖下一關（沒有「送審中」這個中間狀態）。
  - **`photo` / `video`（A2、D5、C5、B6 拍照，E2、E3 錄影）**：隊伍直接在 LINE 對話上傳照片／影片，**系統不會自動過關**，只會回覆「請等待小編確認」並推播通知小編；小編或登記過的關主看過內容沒問題後，輸入「通過 X組」才真正解鎖下一關。
  - `通過 X組` 這個指令**不限關卡類型**，任何一關都可以用它手動解鎖下一關；登記過的關主（見下方「關主自助登記」）也能用，不需要每次都找小編代打。
- **不再有「完賽」自由回報**：計時只能靠隊伍實際人在 B6、由 **B6 終點工作人員**（先登記「我是 B6 關主」）或小編觸發「到站 X組」才會停止；「出發 X組」同樣只有小編、登記過的關主／總領隊能用，隊伍成員與陌生人按了會被拒絕。這是刻意設計成「現場才能觸發」，避免隊伍還沒到站就自稱完賽。
- **不會在 12:30 自動停止受理進度，也不會幫忘記回報的隊伍自動產生成績**：隊伍可能逾時才完成，所以逾時仍可以繼續闖關、實際到站辦理終點確認，只是成績標註「逾時」（出發後超過 2 小時算逾時）。只有小編手動輸入「遊戲結束」才會停止受理新的關卡進度。
- **10 組各有專屬路線順序**（見下方「路線表」），第 10 組比較特別：第 1 關就是 B6，最後一關（B3）破完後直接回 B6 辦終點確認，不需要重做一次 B6 的任務。

## 系統架構

- **Express**：接收 LINE Webhook、提供關卡地圖圖片的靜態網址、後台網頁（`/admin`）
- **@line/bot-sdk v11**：Webhook 簽章驗證、回覆／推播訊息；同時處理文字訊息與圖片／影片訊息
- **PostgreSQL**（`pg` 套件）：資料庫是獨立的 Postgres 服務，不會因為網頁服務重開機／被雲端平台自動關機而遺失資料（詳見下方「部署」的說明）；關卡設定與路線密語也存在這裡，後台網頁編輯的內容一樣不會被重新部署蓋掉
- **node-cron**：12:15 提醒排程（只提醒，不會停止受理進度）

```
src/
  index.js              Express 入口、Webhook 路由（文字走 commandRouter，圖片／影片走 teamService.verifyMedia）
  db.js                 Postgres 連線池、schema、交易 helper
  lineClient.js         LINE SDK 包裝（reply / push）
  scheduler.js          12:15 提醒排程
  config/
    event.js            時間控管參數（12:15 提醒時間 / 逾時的 2 小時上限）
    admins.js            小編（管理員）userId 名單
    checkpoints.json     12 關設定的種子資料（僅第一次啟動、資料庫是空的時候會匯入，之後改動一律在資料庫）
    checkpoints.js        對外相容介面，實際委派給 configStore.js
    teamsRoute.json      10 組路線密語的種子資料（同上，僅第一次啟動匯入）
    teamsRoute.js         對外相容介面，實際委派給 configStore.js
    configStore.js       關卡／路線設定＋加好友歡迎詞真正的讀寫層（資料庫 + 記憶體快取），後台網頁 API 也是呼叫這裡
    imageStore.js         後台網頁上傳的圖片存取層，圖片檔案本身存資料庫（bytea），不是本機硬碟
  admin/
    auth.js               後台網頁登入機制（簽名 cookie，單一共用密碼）
    router.js             後台網頁的路由與 JSON API
  services/
    teamService.js        核心商業邏輯（報到／出發／過關／終點確認／關主登記／排名…）
    timeUtil.js            時間格式化與逾時判斷（出發後經過多久，不是比對當天固定時刻）
  handlers/
    commandRouter.js       文字指令解析與分派
scripts/                  CSV 匯出／匯入工具，讀寫的是資料庫而不是 JSON 檔案（見下方）
public/maps/              專案原本內建、隨 git 部署的示意圖／現場照片放這裡；後台網頁另外上傳的圖片存資料庫，不會出現在這個資料夾
public/admin/             後台網頁前端（純 HTML/JS，無框架）
```

## 活動前必做的事（不需要寫程式）

關卡設定與 10 組路線密語實際存在 Postgres 裡（`checkpoint_configs`／`team_route_configs` 兩張表），第一次啟動時會自動從 `src/config/checkpoints.json`／`teamsRoute.json` 匯入一份初始值當種子資料，之後所有讀寫都走資料庫，不會因為 Render 重新部署而被蓋掉。有兩種編輯方式：

1. **後台網頁**（推薦，活動中隨時可用）：見下方「[後台網頁（/admin）](#後台網頁admin)」，登入後可以直接新增/編輯/刪除關卡、上傳現場照片與地圖位置圖、編輯每組路線密語、新增全新的組別或關卡、即時查看闖關進度與關主名單。
2. **CSV 匯出／匯入**（適合一次性大量編輯、離線用 Excel／Google Sheets 整理，但圖片本身仍需透過後台網頁上傳）：

- ⚠️ **活動前請確認 B6 終點工作人員已登記**：「到站 X組」只有小編或登記在 B6 的關主能用，終點工作人員要先傳「我是 B6 關主」（或「關主報到」再回 B6）。沒登記的人輸入到站會被拒絕並提示怎麼登記；後台網頁「關主名單」分頁可確認 B6 是否已有人登記。
- ✅ **10 組官方路線順序**：已依文件「四、10組正式路線表」寫入（第 10 組的特例——第 1 關是 B6——也已處理好，程式邏輯本身不需要特別分支，因為終點確認一律是獨立動作）。
- ✅ **關卡任務內容、位置、地圖圖片、過關方式**：已依「國介＆禾康 闖關活動細節表」（含 0914 版的補充，例如 E3「請自備礦泉水」）、v2 文件的關主配置、與溪頭步道導覽圖填入。B4「百步穿揚」的位置（星光教室）已確認無誤。每一關可以分開設定兩種圖片：**現場照片**（這關實際長什麼樣子／任務參考照，宣布關卡時先前既有內容）與**地圖位置圖**（怎麼走到這關，新增的獨立欄位）。公布關卡（出發／通過／到站等）改用 **Flex 卡片**呈現：有設定地圖位置圖時當卡片封面，內文整理地點／玩法／過關方式；地圖位置圖不只一張、或有另外設定現場照片時，其餘圖片會接在卡片後面以一般圖片訊息送出，LINE 聊天室看起來比純文字＋一堆散落圖片更像正式活動的公告卡。
- ✅ **2 個密語制關卡（A3、A5）的關鍵字**：目前設計是**每一關 10 組共用同一個關鍵字，就是關卡代號本身**（例如 A3 關的關鍵字就是「A3」、A5 關就是「A5」），不是每組各給不同密語。這樣關主現場只需要記自己那一關的一個字，不需要對照 10 組不同密語的清單。B3、B4、D6、C4 這 4 關則完全不用密語，改成關主現場確認完成後直接輸入「通過 X組」（見上方「遊戲機制」）。答案比對會自動去除頭尾空白、忽略大小寫，同一關也可以用「｜」分隔多個都算對的答案（例如「紅檜｜紅檜木」）。

  ⚠️ 這個設計的取捨：因為關鍵字不再是每組專屬，如果隊伍看到其他組輸入密語、或知道密語是關卡代號本身，理論上可以跳過任務直接輸入過關。防作弊主要依賴「關主確認完成後才告知」這一層，密語本身不再是秘密。如果活動方之後想改回每組不同的密語，用後台網頁或下面的 CSV 流程即可覆蓋，系統會檢查同一關卡的關鍵字在 10 組之間是否一致（目前）或允許各自不同（如果改回每組互不相同的設計）。

```bash
npm run routes:export        # 匯出 -> data/teams-route.csv
#   用 Excel/Sheets 開啟，verifyType 欄位是唯讀參考——只有 'keyword' 的列才要填 keyword，
#   'photo' / 'video' / 'referee' 的列請保持 keyword 欄位空白。存檔後：
npm run routes:import        # 檢查並寫回資料庫
```

> 關鍵字請避開系統保留字：「報到」「關主報到」「出發」「到站」「通過」「退回」「完賽」「使用說明」「進度」「順序」「組別順序」「排行榜」「目前關卡」「闖關進度」「遊戲結束」「重置遊戲」「重置關主」「重置總領隊」「總領綁定」「推播」「接任隊長」「確認換隊長」「解除綁定」「加分」「取消到站」「我的ID」「緊急聯絡」「緊急求助」「處理緊急」，以及所有「數字+組」「我是XX關主」「推播 ...」「群發 ...」的格式（例如「5組」「我是B3關主」「推播 隊長 測試」），系統會先比對這些指令，比對不到才視為關鍵字嘗試。另外，任何關卡的代號或名稱本身（例如「B3」「救救菜英文」）對「不是隊伍成員」的帳號來說會被當成關主報到的捷徑，但這不影響隊伍：已經報到綁定隊伍的人打出這些字，仍會照原本規則走關鍵字比對。

若關卡內容、位置或過關方式之後有異動，一樣可以用 `npm run checkpoints:export` / `checkpoints:import` 編輯（CSV 工作流程用法同上，一樣是讀寫資料庫而不是 JSON 檔案）。

## 環境設定

> 需要 **Node.js 22 以上**（`@line/bot-sdk` v11 的硬性需求）。可用 `node -v` 確認，不夠新的話用 [nvm](https://github.com/nvm-sh/nvm) 或官網安裝新版。

### 本機開發

1. 安裝並啟動本機 PostgreSQL（Mac 用 Homebrew）：
   ```bash
   brew install postgresql@16
   brew services start postgresql@16
   createdb line_checkpoint_dev
   ```
2. 複製 `.env.example` 為 `.env`，填入：
   - `DATABASE_URL=postgres://<你的系統帳號>@localhost/line_checkpoint_dev`，`PGSSL=false`
   - `LINE_CHANNEL_ACCESS_TOKEN`、`LINE_CHANNEL_SECRET`（見下方 LINE 設定）
   - `ADMIN_USER_IDS`：小編（可用全部管理指令的人）的 LINE userId，多人用逗號分隔
   - `PUBLIC_BASE_URL`：伺服器對外網址（LINE 平台會來抓地圖圖片，必須是 https）
   - `EMERGENCY_PHONE`（選填）：緊急聯絡的回覆訊息會附上「情況危急請直接撥打：這支號碼」，建議填現場總召或小編的手機
3. 安裝套件並啟動：
   ```bash
   npm install
   npm start
   ```
   第一次啟動會自動建立資料表（見 `src/db.js` 的 `init()`）。
4. 本機測試可用 `ngrok http 3000`（或 cloudflared）取得暫時 https 網址，設定回 `.env` 的 `PUBLIC_BASE_URL`，並到 LINE Developers Console 的 Webhook URL 填 `https://your-ngrok-domain/webhook`，開啟「Use webhook」。
5. LINE 官方帳號後台記得把「自動回覆訊息」關閉，否則圖片／影片訊息可能會先被官方帳號內建的自動回覆擋掉。

### LINE 官方帳號設定 Messaging API

如果你的 LINE 官方帳號原本只有在用「LINE Official Account」介面（發群發訊息、圖文選單那種），Messaging API 是另一個要另外啟用的頁籤，兩者可以掛在同一個官方帳號上：

1. 到 [LINE Developers Console](https://developers.line.biz/console/)，用同一組 LINE 帳號登入
2. 建立一個 Provider，底下建立 **Messaging API Channel**（會掛到你現有的官方帳號，不會變成兩個帳號）
3. 進去該 Channel 的「Messaging API」頁籤：取得 **Channel access token**、**Channel secret**，設定 **Webhook URL** 為 `https://你的網址/webhook` 並開啟「Use webhook」
4. **務必**把「自動回應訊息」「加入好友歡迎訊息」都關閉——加入好友的歡迎詞已經改由這支程式的 `follow` 事件處理（文字內容存資料庫，可在後台網頁「加好友歡迎詞」分頁編輯），LINE 官方帳號介面內建的版本如果沒關，加好友時會收到兩則重複、內容可能互相矛盾的歡迎訊息

### 部署到 Render（免費方案可行，但有一個重要前提）

Render 免費的網頁服務（Web Service）檔案系統是暫時性的：只要閒置 15 分鐘被自動關機、下次請求進來喚醒，本機檔案就會被清空。**這就是這個系統改用 Postgres、而不是本機 SQLite 檔案的原因**——資料庫是獨立服務，網頁服務重開機不會動到它。做法：

1. Render 建立一個 **PostgreSQL** 服務（免費方案即可，一個資料庫 30 天效期，活動前一兩天建立即可涵蓋整個活動）
2. 複製它的 **Internal Database URL**，貼到 Render 網頁服務的環境變數 `DATABASE_URL`（Render 內部連線預設會用 SSL，`.env.example` 裡的 `PGSSL` 可以不用設）
3. 建立 Render **Web Service**，指到這個專案的 repo，Build Command 用 `npm install`、Start Command 用 `npm start`
4. 把 `.env` 裡其他變數（`LINE_CHANNEL_ACCESS_TOKEN`、`LINE_CHANNEL_SECRET`、`ADMIN_USER_IDS`、`PUBLIC_BASE_URL` 設成 Render 給的網址）也加進 Render 的環境變數
5. 免費方案仍然會閒置關機、下個請求要等約 1 分鐘喚醒——活動當天報到開始前，記得先手動 `curl` 一次 `/health` 把服務叫醒，並且活動全程盡量保持有人陸續在傳訊息（自然就會一直保持喚醒狀態）

### 如何取得某人的 LINE userId（設定 ADMIN_USER_IDS 用）

讓要設定為小編的帳號傳一句話給官方帳號，伺服器 log 會印出 `收到訊息：userId=... type=...`，複製那個 userId 即可。

### 後台網頁（/admin）

給小編用的網頁後台，不用重新部署就能編輯關卡與路線設定，也能看即時進度：

- 網址：`https://你的網址/admin`（本機開發是 `http://localhost:3000/admin`）
- 需要先在環境變數設定：
  - `ADMIN_PANEL_PASSWORD`：登入用的共用密碼，交給要編輯內容的小編
  - `ADMIN_PANEL_SECRET`：登入 cookie 的簽名密鑰，隨便一段長亂碼即可（Render 部署時 `render.yaml` 已設定自動產生，不用手動填）
- 登入後可以做的事：
  - **關卡設定**：編輯每一關的名稱、地點、內容說明、計分方式、通關方式（密語／照片／影片／關主直接喊過），分開上傳／刪除**現場照片**與**地圖位置圖**兩種圖片，也可以新增全新的關卡代號。上傳的圖片存在資料庫（不是網頁服務本機硬碟），Render 重新部署或閒置喚醒都不會遺失
  - **組別路線**：編輯每組的過關順序與密語，也可以新增全新的組別編號（例如活動當天多開一組）、或刪除整組路線
  - **即時進度**：看每組目前狀態（尚未報到／已報到／闖關中／已終點確認）、進度、經過時間、是否逾時、目前累計加分（小編用「加分 X組 N」指令加減的分數）；同一頁也有「重置整場遊戲」按鈕（等同 LINE 指令「重置遊戲 確認」），需要瀏覽器確認＋輸入「確認重置」兩層才會真的執行。另外有「關卡公告推播對象」下拉選單，可切換每次過關公告（出發／通過／到站等 groupBroadcast）要**只推隊長**（預設，現場隊伍本來就在一起、隊長口頭轉達即可，可大幅減少 LINE Messaging API 計費的推播則數）還是**推全組成員**，存在資料庫（`app_config` 表），切換立即生效，「重置遊戲」不會動到這個設定
  - **後台出發／到站**（即時進度分頁上方）：每組的耗時與逾時都以「出發時間」為起點，所以後台可以直接按 **🚩 出發**（等同 LINE 指令「出發 X組」）與 **🏁 到站**（等同「到站 X組」，B6 終點確認）。表格每列有單組按鈕，也可以勾選多組一起出發／到站；時間欄位不填＝按下去的當下，現場已經先出發或到站、晚一點才登記時可以**補登實際時間**（不能是未來、不能早於 24 小時前；到站時間不能早於該組出發時間）。表格會顯示每組的出發時間與到站時間。出發後會推播第一關給隊伍並通知第一關關主，按錯用進度表每列的按鈕更正。若 LINE 通知推播失敗，出發／到站仍已記錄，畫面會提醒你手動通知
  - **進度表單組操作與自動更新**：表格多了「目前關卡」欄，每列依狀態出現按鈕——**✅ 通過**（放行目前這一關並推播下一關，等同 LINE「通過 X組」，小編權限、任何關卡類型都能用，適合關主關卡沒人回報時）、**↩ 退回**（退一關，已到站的一併取消到站）、**取消到站**（只取消終點確認，關卡數不變）。這些都有二次確認、效果與 LINE 指令完全相同（同一個底層函式）。此頁停在畫面上時每 10 秒自動更新，勾選中的組別重畫後會保留。
  - **指定關主／總領隊**（「關主名單」「總領隊名單」分頁）：小編可以直接從**傳過訊息給官方帳號的人**裡挑名字指定關卡或總領隊，不用複製 userId，也不用等對方自己登記；被指定的人會收到 LINE 通知與該身分的指令說明，名單旁有「移除」按鈕可取消（對方同樣會收到通知）。下拉選單標出每個人現有的身分，已在隊伍裡的人不能指定（跟自助登記同樣規則，避免自己核准自己）。名單來源是 `line_users` 資料表：每次有人傳訊息或加好友就記錄（顯示名稱只在缺的時候才問 LINE 一次），啟動時會把既有的隊伍成員／關主／總領隊補進去。⚠️ LINE 沒有「列出全部好友」的公開 API，所以**對方至少要傳過一句話**（例如「我的ID」）才會出現在名單；重置遊戲不會清掉這張表。
  - **關主名單**：看目前有哪些 LINE 帳號登記成哪一關的關主（只顯示 userId 末 6 碼）
  - **小隊長名單**：看每一組目前的隊長是誰（只顯示 userId 末 6 碼）、報到狀態、報到時間，方便對照「推播 隊長」實際會送到哪些人
  - **總領隊名單**：看目前有哪些 LINE 帳號自助登記為總領隊（只顯示 userId 末 6 碼）、登記時間
  - **照片／影片審核**（小編快速通過：LINE 通知底下有「✅ 通過 X組」一鍵按鈕，點一下等同輸入指令；通知也附後台連結 `/admin#submissions` 直接開啟此分頁；分頁停留時每 8 秒自動更新，分頁標籤與瀏覽器標題會顯示待審核數量；影片支援 Range 分段讀取，iPhone／Safari 也能播）：隊伍在沒有關主的關卡上傳照片／影片後，實際內容會直接顯示在這一頁（存在資料庫，不是本機硬碟；影片超過 15MB 不會存，退回舊的「請至聊天記錄確認」文字通知；**影片要等 LINE 轉檔完成才抓得到完整內容**，系統會先查 LINE 的「內容準備狀態」（最多等 25 秒），下載後再檢查 HTTP 狀態、大小與檔案格式，任何一項不合格就不存，改走文字通知，不會出現放不出來的卡片；預覽萬一還是載入失敗，卡片會直接顯示原因——檔案是空的、iPhone 的 HEVC／HEIC 格式瀏覽器不支援、登入過期——並提供「下載檔案」連結），不用再去 LINE 聊天記錄裡翻。按「✅ 通過」效果等同 LINE 指令「通過 X組」，會直接推播下一關公告給隊伍；按「🗑 移除」只是清掉這筆待審核紀錄，不影響隊伍進度。隊伍通過任何一關、或被「解除綁定」、或「重置遊戲」，該組所有待審核紀錄都會自動清空
  - **加分紀錄**：每一筆「加分 X組 N」的明細（組別、分數、理由、操作人末 6 碼、時間），最新的排最前面
  - **加好友歡迎詞**：編輯加好友時自動回覆的歡迎訊息文字，存在資料庫（`app_config` 表），編輯後立即生效不用重新部署
  - **指令說明**：完整指令參考表（依角色分類：隊伍／關主／B6工作人員／總領隊／小編），**只有登入後台才看得到，隊伍跟小隊長不會知道有這些指令**——這是刻意設計成後台專屬頁面，跟公開的 LINE「使用說明」（只教基本報到／過關流程）分開
- 登入頁有「顯示／隱藏密碼」切換按鈕，方便用手機小螢幕輸入時確認打對
- 登入是單一共用密碼＋簽名 cookie（12 小時有效），沒有個別帳號區分，適合小編團隊內部共用，不建議把密碼外流給參賽隊伍

⚠️ 目前是單一共用密碼、沒有操作紀錄（誰改了什麼），如果活動規模擴大到需要多人分權限或稽核紀錄，這是之後可以加強的方向。

### 圖文選單（Rich Menu）

聊天室下方固定顯示的選單，2 欄 × 3 列共六個按鈕，分別送出固定文字：`目前關卡`／`闖關進度`／`排行榜`／`報到`／`使用說明`／`緊急聯絡`（最後一顆用紅色底標示）。設計取材自「森呼吸．永續漫遊」主視覺配色與雙公司 LOGO。

「報到」是特別設計給第一次使用、還沒加入任何組別的人：點下去機器人會回覆「請回覆您的組別編號」，這時候不需要記住完整指令格式，直接回「1組」或「第一組」就會完成報到（見下方「指令一覽」的彈性格式說明）。

- 設計圖產生腳本：`scripts/generate-richmenu.py`（用系統內建的 STHeiti 字型畫圖，改文字/配色/按鈕內容後重跑即可）
- 素材放在 `assets/brand/logo.jpg`（雙公司 LOGO），輸出到 `assets/richmenu.png`
- 上傳到 LINE、設成所有人的預設選單：
  ```bash
  python3 scripts/generate-richmenu.py   # 有改設計才需要重跑
  LINE_CHANNEL_ACCESS_TOKEN=xxx node scripts/setup-rich-menu.js
  ```
  重複執行是安全的：腳本會先刪除帳號上所有既有選單再重建，不會累積殘留。

> 圖文選單按鈕**只能送出固定文字**，不能像「出發 X組」那樣讓使用者自己填組別編號，所以選單只放了不需要參數的查詢類指令；小編／關主/B6工作人員需要指定組別的指令仍維持手動輸入。

## 指令一覽

> 以下所有「X組」都支援彈性格式：阿拉伯數字或中文數字都可以（`1組`／`一組`），「第」字可加可不加（`第1組`／`1組`），動詞在前在後都可以（`出發1組`／`1組出發`）。「報到」比較特別，動詞本身也可以省略——點圖文選單「報到」按鈕後，之後單獨回覆組別（例如「第一組」）就會完成報到。

| 指令 | 使用者 | 說明 |

| `報到`／`報到 X組`／單獨回覆「X組」 | 隊長／組員 | 首位報到者為隊長，之後為組員；單獨輸入「報到」會提示回覆組別編號 |

| `處理緊急 N`（點警報底下的「我來處理」按鈕即可） | 小編 | 接手緊急聯絡 #N：回覆回報者「小編已收到並處理中」，並告知其他小編已有人接手，避免重複前往。後台分頁的「已處理」按鈕效果相同。「重置遊戲」會一併清空緊急聯絡紀錄 |
| `我的ID` | 任何人 | 回覆自己的 LINE userId。用途：要新增小編時，請對方傳這個指令，把回覆的 userId 貼進環境變數 `ADMIN_USER_IDS`（逗號分隔多個）後重新部署即可生效；`ADMIN_USER_IDS` 不是在後台網頁設定，只能改環境變數。 |

### 關主自助登記機制

> **登記／報到成功後會自動附上該身分可用的指令說明**：隊長、組員、關主、總領隊各自收到一則專屬的指令清單（只列自己身分能用的，不含小編專用指令）。組員的說明會額外提醒「目前關卡公告只會推播給隊長」（當推播範圍設為只推隊長時），避免組員以為沒收到訊息是系統壞掉。

B3、B4、D6、C4 這 4 關的關主，或協助審核照片／影片的關主，都可以自己在 LINE 傳「我是 B3 關主」（換成自己負責的代號）完成登記，不需要小編手動維護 userId 名單。登記後這個帳號的「通過 X組」只對登記的那一關生效——例如登記為 B3 關主的人，對一組還在 D5 的隊伍打「通過」會被拒絕，只有那組真的走到 B3 才能核准。

也可以走比較口語化的兩步驟流程：先傳「關主報到」（「關主綁定」「報到 關主」也可以），系統會提示回覆關卡代號或名稱；接著單獨回覆「B3」或「救救菜英文」（代號、遊戲名稱都可以，不分大小寫）就完成登記，效果跟「我是 B3 關主」完全一樣。這個單獨回覆的捷徑只對「目前不是任何隊伍成員」的帳號生效——已經報到綁定隊伍的人打出跟關卡同名的字，不會被誤判成要登記關主，會照原本的規則繼續走關鍵字比對，避免兩種身分互相干擾。

登記後，只要有隊伍出發／通過上一關而正往這一關前進，就會自動收到「第 X 組正往您這關來」的推播；輸入「進度」也能查詢跟自己這關有關的組別（已出發還在路上的、已經抵達等待確認的），不用被動等隊伍走到面前才知道。

⚠️ 安全性取捨：登記本身是開放的，系統不會驗證這個人是不是真的關主。唯一的防護是「已經報到綁定隊伍的帳號不能登記」，擋掉最直接的作弊路徑（隊伍自己登記自己那關的關主、幫自己過關）。如果現場人力複雜、擔心有人冒充，可以考慮之後加上小編審核登記的機制，目前為了讓關主能自助、不需要小編介入，先採用這個較簡單但仍有基本防護的做法。

### 總領隊自助登記與群發機制

設計動機:活動總召／協調人員不一定是系統裡設定的 `ADMIN_USER_IDS`（小編），但仍需要能對所有小隊長發送公告（例如集合時間異動、天氣狀況通知）。做法跟關主自助登記完全一樣：自己傳「總領綁定」完成登記，之後輸入「推播」就能選擇對象（隊長、關主、所有人）發送訊息，例如「推播 隊長 集合時間改九點」。同一個 LINE 帳號可以同時登記為關主又是總領隊，兩者互不影響、互不排斥。

⚠️ 安全性取捨與關主自助登記相同：任何非隊伍成員的帳號都能自助登記為總領隊，系統不會額外驗證身分。緩解方式同樣是活動前跟工作人員說明這個指令、可在後台網頁「總領隊名單」分頁確認實際登記的人數是否合理，發現異常用「重置總領隊」清空重來。

### 關於「到站 X組」的設計選擇

v2 文件把「B6 終點怎麼停止計時」列為待確認事項，列出三個方案（固定密碼／系統動態產生一次性代碼／QR Code），文件建議用「現場工作人員一次性代碼，隊長輸入」。討論後我們選了**功能等價、但更簡單可靠的做法**：不是隊長輸入代碼，而是**B6 工作人員直接輸入「到站 X組」**——跟現有「出發 X組」完全相同的模式（現場角色觸發、不需要另外的權限分級）。安全性一樣是「只有人在現場才能觸發」，但少了「代碼產生→念給隊長→隊長輸入」這三個步驟，也不需要另外維護代碼的產生與過期邏輯。如果之後想改成隊長輸入代碼的版本，改動範圍在 `teamService.finishAtB6` 與 `commandRouter.js` 的 `到站` 分支。

## 與文件的實作對應說明

- 文件狀態①已報到／②待出發在系統裡合併為單一狀態 `CHECKED_IN`：文件中這兩個階段之間沒有獨立觸發指令，行為描述相同（尚未計時、不公布關卡地點）。
- 排名規則只定義了「已終點確認」隊伍之間的排序。本系統把所有隊伍分兩桶：準時終點確認排最前面，其餘（逾時終點確認、闖關中、尚未出發）都算後段，桶內再依「完成關卡數＋小編手動加分」、總耗時排序；尚未有總耗時的隊伍並列在同關卡數的最後。加分視同多完成幾關，所以能在桶內排序中真的把名次往前拉，但不能讓還沒終點確認的組別排到已準時終點確認的組別前面（桶的優先度更高）。
- **「準時／逾時」是看該組自己出發後經過多久，不是比對當天固定的 12:30 時刻**：每組從「出發」算起，`event.maxDurationMinutes`（預設 120 分鐘）內辦理終點確認都算準時，超過算逾時。這樣萬一某組出發得比較晚，也不會因為公版時刻而被不公平地判定逾時。系統沒有任何固定時刻的自動停止機制，隊伍逾時仍可繼續闖關與辦理終點確認；只有小編手動「遊戲結束」才會停止受理新進度。
- B4「星光教室」的位置：文件與溪頭步道導覽圖原本都標註為「推測」，已向活動方確認無誤，`public/maps/B4-1.jpg`／`B4-2.jpg` 目前是現場實拍照片，不再是示意地圖。

## 已知風險與對應的保護措施

實作過程中發現並修掉的幾個邊界情況，記錄下來方便之後維護：

- **「通過」現在會檢查是否已凍結進度**：一開始只有關鍵字比對會擋「遊戲結束」後的新進度，「通過」被漏掉了，導致小編理論上可以在凍結後繼續把任何一組從頭推到尾。已修正為兩者行為一致。
- **報到會驗證組別編號**：`報到 99組` 這種不存在的組別以前會被接受，之後只要碰到「出發」之類需要讀路線表的指令就會拋例外、使用者完全沒有任何回覆。現在報到時就會直接拒絕不合法的組別編號。
- **任何未預期的伺服器錯誤，使用者都會收到保底回覆**（「系統發生錯誤，請稍後再試」），而不是完全沒有回應——這樣使用者才知道是系統出狀況，而不是以為訊息沒送出去。
- **`通過`／`到站` 都沒有辦法事前防止手滑重複觸發**（`通過` 不像 `出發`／`到站` 天然冪等，連按兩次會多跳一關）；沒有做成事前攔截是因為早期版本試過用時間或關卡索引去猜測「這是不是重複」，但小編合理的快速連續操作（一次確認好幾組不同的送審）反而會被誤判擋掉。改用**事後可以更正**的方式：`退回 X組` 退一關、`取消到站 X組` 取消誤按的到站，比起自動偵測「是不是手滑」更可靠。
- **「我是 XX 關主」目前任何人都能自助登記**，唯一的防護是擋掉已經報到綁定隊伍的人（防止隊員自己核准自己過關）。如果活動當天有非隊員、非工作人員的訪客誤傳這句話，理論上可以搶先登記成某一關的關主；緩解方式是活動前跟工作人員說明這個指令、實際登記狀況可以到後台網頁「關主名單」隨時查看，發現異常用「重置關主」清空重來。
- **後台網頁（`/admin`）是單一共用密碼、沒有個別帳號與操作紀錄**：登入 cookie 有效期 12 小時，簽出後的 cookie 在自然過期前無法從伺服器端強制註銷（登出只是讓瀏覽器端清掉 cookie）。這對單一活動、小編團隊內部共用是合理的取捨，但密碼不能外流給參賽隊伍或其他無關人員。

## 自動化測試

`tests/commandRouter.test.js` 用 Node 內建的 `node:test` 涵蓋了報到（含無效組別）、出發、關鍵字解謎、照片／影片送審與小編通過、關卡型態不符提示、凍結後拒絕通過、退回更正（含已到站後退回）、取消到站、到站終點確認、管理指令權限、遊戲結束凍結、換隊長、解除綁定、排行榜開關、重置遊戲等核心流程。測試需要連到一個 Postgres（預設接本機的 `line_checkpoint_test`，每個測試開頭都會先重置遊戲、彼此不會互相汙染）：

```bash
createdb line_checkpoint_test   # 只需要建立一次
npm test
```

也可以用 `TEST_DATABASE_URL` 指到其他 Postgres（例如另一台機器）：
```bash
TEST_DATABASE_URL=postgres://user:pass@host/db npm test
```

修改 `src/services/teamService.js` 或 `src/handlers/commandRouter.js` 後，建議先跑一次確認沒有破壞既有行為。
